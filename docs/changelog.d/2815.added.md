- `LedgerEnforcement` checks `tasks/lessons.md` in each PR against the Lessons Retro contract: every non-blank line belongs to a parsed entry, the required and known fields, the `Missed by` values, a cumulative `Seen` for each theme, a resolving `Enforced by` path or rule id, `Promoted` at `Seen` 3× or more with `Enforced by: judgment`, and every `Triggered by correction` reference of the merge-base. References bound `Seen` from above: an entry adds at most the references that the earlier entries of its theme do not name, a theme maximum never falls, and a consolidation keeps the maximum and adds only the consolidating PR. A theme corresponds to the merge-base theme with the same `Mistake pattern`, or, after a rename, to the removed theme that shares its references. Each finding names the entry, the field and the fix. An existing `Enforced by` reference stops at human review. A theme state that the merge-base already has is reported as carried and does not fail. `scripts/check-ci.sh ledger --base <ref>` runs it; the new `LedgerEnforcement` CI job runs on each PR with code and on a documentation-only PR that changes the ledger, and its failure fails `Required / CI`. `scripts/maintenance-triage.sh --entries <file>` prints the parsed entries with the lines that each entry owns, so the ledger keeps one parser; a repeated field in one entry now keeps its first value.
