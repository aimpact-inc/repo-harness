- `LedgerEnforcement` checks `tasks/lessons.md` in each PR against the Lessons Retro contract: the required fields, the `Missed by` values, a cumulative `Seen` for each theme, a resolving `Enforced by` path or rule id, `Promoted` at `Seen` 3× or more with `Enforced by: judgment`, and every `Triggered by correction` reference of a merged entry. Each finding names the entry, the field and the fix. An existing `Enforced by` reference stops at human review. A theme state that the base already has is reported as carried and does not fail. `scripts/check-ci.sh ledger --base <ref>` runs it; the new `LedgerEnforcement` CI job runs on each PR with code and on a documentation-only PR that changes the ledger, and its failure fails `Required / CI`. `scripts/maintenance-triage.sh --entries <file>` prints the parsed entries for the check, so the ledger keeps one parser.
