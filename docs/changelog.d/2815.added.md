- `LedgerEnforcement` checks `tasks/lessons.md` in each PR against the Lessons Retro contract: every lesson line belongs to a parsed entry, the required and known fields, the `Missed by` values, a cumulative `Seen` for each theme (a new entry adds exactly 1 and names a new correction; a new theme starts at 1×), a resolving `Enforced by` path or rule id, `Promoted` at `Seen` 3× or more with `Enforced by: judgment`, and every `Triggered by correction` reference of a merged entry. The change is measured from the merge-base with the PR base. Each finding names the entry, the field and the fix. An existing `Enforced by` reference stops at human review. A theme state that the merge-base already has is reported as carried and does not fail; a rename or delete of such a theme fails unless the rule is promoted or enforced. `scripts/check-ci.sh ledger --base <ref>` runs it; the new `LedgerEnforcement` CI job runs on each PR with code and on a documentation-only PR that changes the ledger, and its failure fails `Required / CI`. `scripts/maintenance-triage.sh --entries <file>` prints the parsed entries with the line of each field, so the ledger keeps one parser; a repeated field in one entry now keeps its first value.
