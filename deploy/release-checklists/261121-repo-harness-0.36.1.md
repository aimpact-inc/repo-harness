## Upgrade

- Run `rh update` once on each host. The update moves the host configuration ledger from protocol 4 to 5 and saved settings to the 11-seat schema. Review renamed seats and routing. Relaunch after all participating hosts update.
- Record fresh acceptance for open reviews that use the old receipt layout. Pass `--seat gatekeeper` or `--seat reviewer` when you publish acceptance manually.
- For Antigravity, run `rh install --target antigravity` to opt in or `rh update --target antigravity` to refresh managed entries. Run `rh doctor` and check the actual hook command paths. Record guard activation in fresh `agy` sessions for #3251 and native advisor launch and Stop handoff in Herdr for #3246.
- After a successful `rh arch debt --base <ref>` run, remove the retired `.git/repo-harness/cache/arch-debt` cache if it exists. In a linked worktree, check under the directory that `git rev-parse --git-common-dir` prints.
- See the full [0.36.1 upgrade instructions](../../docs/CHANGELOG.md#upgrade).

## Order of the owner steps

After the prep PR merges and the owner gives the explicit release word, run `git fetch origin` and then `bash scripts/release-owner-steps.sh plan 0.36.1` from the main checkout. Keep the plan. It binds each command to the merged release commit.

1. Create the detached release worktree at the commit from the plan. Run `bun install --frozen-lockfile` and `bun run check:release` there.
2. Run the plan's guard and publish `repo-harness-operator-web@0.36.1` from `packages/operator-web`.
3. Wait for npm to show the Operator Web version. Run the guard again and publish `repo-harness@0.36.1` from the release worktree root.
4. Wait for npm to show the core version. Run `bash scripts/release-owner-steps.sh check published 0.36.1` to verify both packages.
5. Create the annotated tag `v0.36.1` at the release commit and push the tag.
6. Extract the notes with `bash scripts/release-owner-steps.sh notes 0.36.1`. Create the GitHub Release from those notes and the verified tag.
7. Run `bash scripts/release-owner-steps.sh check tagged 0.36.1`.
8. Run `bun scripts/check-released-managed-values.ts --write`. Submit the generated index in one Low PR.

If a step stops, use the saved plan's resume checks to determine which steps already succeeded.

## Rollback

Before publication, close the prep PR or run `git revert <squash-commit>` after merge. After publication, keep the tag and release a corrective patch.

Version 0.35.2 rejects protocol 5 host configuration ledgers. Keep 0.36.1 on migrated hosts, or restore the pre-upgrade ledgers with their matching host state and seat settings before you return to 0.35.2. Move native `agy` seats to a supported runtime first. If the host state restore excludes Antigravity, use 0.36.1 to remove its managed entries before you restore the old state.
