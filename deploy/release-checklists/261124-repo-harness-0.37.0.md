## Upgrade

- Run `rh update` once on each host after installing 0.37.0. Existing 0.36.1 configurations with a stored `seats` section fail closed with `seats_config_migration_required` until `rh update` applies the one-shot `worker-neon-deep` migration and refreshes staged Antigravity skills and hooks.
- `rh update` installs `PreToolUse.question` (`question-guard`) on Claude (6 -> 7 routes) and Pi (5 -> 6 routes). Relaunch hand-started orchestrator sessions without `REPO_HARNESS_SEAT=orchestrator` with `rh seats launch orchestrator --repository-id <id> --cwd <repo> --task <prompt>`.
- `seats.advisor` accepts `gh` as an opt-in; when granted, it allows only `gh issue comment`, `gh pr comment` and `gh issue create`.
- Review receipts require protocol 3 (`trigger` required on every `P0` or `P1` finding). Finish or rerun in-flight 0.36.1 review seats before collecting under 0.37.0.
- Runtime dependencies update to `@botiverse/oar` `0.129.1` and `herdr-core` `0.1.22`.
- See the full [0.37.0 upgrade instructions](../../docs/CHANGELOG.md#upgrade).

## Order of the owner steps

After the prep PR merges, run `git fetch origin` and then `bash scripts/release-owner-steps.sh plan 0.37.0` from the main checkout. Keep the plan. It binds each command to the merged release commit.

1. Create the detached release worktree at the commit from the plan. Run `bun install --frozen-lockfile` and `bun run check:release` there.
2. Run the plan's guard and publish `repo-harness-operator-web@0.37.0` from `packages/operator-web`.
3. Wait for npm to show the Operator Web version. Run the guard again and publish `repo-harness@0.37.0` from the release worktree root.
4. Wait for npm to show the core version. Run `bash scripts/release-owner-steps.sh check published 0.37.0` to verify both packages.
5. Create the annotated tag `v0.37.0` at the release commit and push the tag.
6. Extract the notes with `bash scripts/release-owner-steps.sh notes 0.37.0`. Create the GitHub Release from those notes and the verified tag.
7. Run `bash scripts/release-owner-steps.sh check tagged 0.37.0`.
8. Run `bun scripts/check-released-managed-values.ts --write`. Submit the generated index in one Low PR.

If a step stops, use the saved plan's resume checks to determine which steps already succeeded.
